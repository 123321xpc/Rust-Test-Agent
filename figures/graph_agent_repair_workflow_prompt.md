# Graph 智能体修复流程图：生成说明

## 图中流程

问题描述与 Rust 仓库 → Navigator 定位问题并尝试复现 → 动态路由：

- 简单问题：直接交给 Fixer 实施修复。
- 复杂问题：先由 Architect 制定修复方案，再交给 Fixer。

修复后，依次进行自动检查和 Verifier 独立审查，然后输出补丁。检查或审查发现问题时，系统可根据反馈返回修复、重新规划或重新定位；预算耗尽时也可能输出尚待验证的补丁。

实现依据：`baselines/graph/multi_agent.py` 中的 `route_after_navigation`、`AGENT_GRAPH_EDGES` 和 `run_graph_agent`，以及 `baselines/graph/agent_prompts.py` 中的角色定义。

## 绘图模型提示词

生成一张用于中文科研汇报 PPT 的简洁流程图。横向 16:9，白色背景，扁平化矢量风格，深色大字，少量蓝绿色，箭头清楚，留白充足。不要照片、三维效果、装饰或水印。

标题为“Graph 智能体修复流程”。从左向右排列：

1. 输入：“问题描述 + Rust 仓库”。
2. “定位与复现”，下方标注“Navigator”。
3. 菱形“动态路由”，分成两条路径：标注“简单”的路径直接进入 Fixer；标注“复杂”的路径先经过“修复规划 / Architect”，再进入 Fixer。
4. 两条路径汇合于“实施修复 / Fixer”。
5. 依次连接“自动检查 / 编译 / 测试”、“独立审查 / Verifier”和“补丁输出”。

从检查与审查区域画一条虚线反馈回路，返回前面的智能体工作区，标注“未通过：修复 / 重规划 / 重定位”。在底部注明：“预算耗尽时可能输出待验证补丁”。所有中文准确清晰，不添加其他文字。确保简单路径不经过 Architect，复杂路径经过 Architect，两条路径都汇入 Fixer，流程线不交叉。
